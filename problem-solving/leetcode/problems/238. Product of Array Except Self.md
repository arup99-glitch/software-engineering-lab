# Product of Array Except Self — Prefix & Suffix (Optimal, O(1) Extra Space)

## Problem

Given an integer array `nums`, return an array `answer` such that `answer[i]` is equal to the product of all the elements of `nums` except `nums[i]`.

The product of any prefix or suffix of `nums` is guaranteed to fit in a 32-bit integer.

You must write an algorithm that runs in `O(n)` time and **without using the division operation**.

**Example 1:**
```
Input: nums = [1,2,3,4]
Output: [24,12,8,6]
```

**Example 2:**
```
Input: nums = [-1,1,0,-3,3]
Output: [0,0,9,0,0]
```

## The Core Idea

For every index `i`, the answer is:

```
res[i] = (product of everything to the LEFT of i) × (product of everything to the RIGHT of i)
```

Instead of building two separate arrays (`prefix[]` and `suffix[]`) to store these products, we can be clever:

1. **First pass:** store the *left products* directly into the result array.
2. **Second pass:** multiply the result array in-place by the *right products*, using a single running variable instead of a whole array.

This gets us down to **O(1) extra space** (not counting the output array itself, which the problem requires us to return anyway).

## Code

```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int n = nums.size();
        vector<int> res(n, 1);

        for (int i = 1; i < n; i++) {
            res[i] = res[i - 1] * nums[i - 1];
        }

        int postfix = 1;
        for (int i = n - 1; i >= 0; i--) {
            res[i] *= postfix;
            postfix *= nums[i];
        }
        return res;
    }
};
```

## Walking Through an Example

```
nums = [1, 2, 3, 4]
n = 4
```

### Step 1 — Initialize `res` with all 1s

```
res = [1, 1, 1, 1]
```

### Step 2 — First pass (left to right): fill `res[i]` with product of everything LEFT of `i`

The loop starts at `i = 1` (index 0 has nothing to its left, so it stays `1`).

Formula used: `res[i] = res[i - 1] * nums[i - 1]`

| i | res[i-1] | nums[i-1] | res[i] = res[i-1] * nums[i-1] |
|---|----------|-----------|-------------------------------|
| 1 | res[0]=1 | nums[0]=1 | res[1] = 1 * 1 = 1 |
| 2 | res[1]=1 | nums[1]=2 | res[2] = 1 * 2 = 2 |
| 3 | res[2]=2 | nums[2]=3 | res[3] = 2 * 3 = 6 |

After this pass:

```
res = [1, 1, 2, 6]
```

Check it manually — this should be the product of all elements *strictly to the left* of each index:
- `res[0]` = nothing to the left = 1 ✅
- `res[1]` = just `nums[0]` = 1 ✅
- `res[2]` = `nums[0] * nums[1]` = 1*2 = 2 ✅
- `res[3]` = `nums[0] * nums[1] * nums[2]` = 1*2*3 = 6 ✅

### Step 3 — Second pass (right to left): multiply in the product of everything RIGHT of `i`

We use a running variable `postfix`, starting at `1` (since there's nothing to the right of the last index).

Formula used each iteration:
```
res[i] *= postfix;      // apply right-product BEFORE updating postfix
postfix *= nums[i];     // now include nums[i] for the NEXT (left) index
```

| i | res[i] before | postfix (before update) | res[i] after (res[i] *= postfix) | postfix after (postfix *= nums[i]) |
|---|----------------|--------------------------|-----------------------------------|-------------------------------------|
| 3 | 6 | 1 | 6 * 1 = **6** | 1 * nums[3]=4 → 4 |
| 2 | 2 | 4 | 2 * 4 = **8** | 4 * nums[2]=3 → 12 |
| 1 | 1 | 12 | 1 * 12 = **12** | 12 * nums[1]=2 → 24 |
| 0 | 1 | 24 | 1 * 24 = **24** | 24 * nums[0]=1 → 24 |

Final result:

```
res = [24, 12, 8, 6]
```

**Verify manually:**
- `res[0]` = 2*3*4 = 24 ✅
- `res[1]` = 1*3*4 = 12 ✅
- `res[2]` = 1*2*4 = 8 ✅
- `res[3]` = 1*2*3 = 6 ✅

All correct! 🎉

## Why This Works — The Key Insight

Every answer `res[i]` is just:

```
res[i] = (left product up to i) × (right product from i)
```

We compute the **left products** first and store them directly in `res`. Then, instead of allocating a second array for **right products**, we walk from right to left, keeping a single running `postfix` variable that represents "the product of everything to the right of the current index seen so far." We multiply it into `res[i]` on the fly.

The order inside the loop matters:
```cpp
res[i] *= postfix;      // (1) use the RIGHT-product accumulated so far — does NOT yet include nums[i]
postfix *= nums[i];     // (2) now fold in nums[i] so the next (more-left) index gets it
```
This ordering guarantees `nums[i]` itself is never multiplied into `res[i]` — exactly what "except self" requires.

## Why Two Passes Instead of One?

- You need the **complete left-product** for a given index before you can combine it with the **right-product** — and the right-product isn't known until you've scanned from the end.
- Doing it in two separate, simple passes (rather than trying to interleave them) keeps the logic clean and avoids needing to store both directions at once.

## Complexity

- **Time: O(n)** — two simple linear passes over the array.
- **Space:**
  - **O(1) extra space** — only a single `postfix` variable is used besides the output array.
  - **O(n) space for the output array** — required since the problem asks us to return the result array (this doesn't count against the "extra space" constraint).

## Comparison to the Naive Prefix/Suffix Approach

| Approach | Time | Extra Space |
|---|---|---|
| Separate `prefix[]` and `suffix[]` arrays | O(n) | O(n) |
| **This optimal approach (reuse `res[]`, single `postfix` var)** | O(n) | **O(1)** |

The optimal version keeps the same time complexity but eliminates the need for two additional full-sized arrays, since the result array itself is reused to hold intermediate prefix values before being finalized with postfix values.

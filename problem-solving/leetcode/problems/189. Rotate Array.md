# Rotate Array — Extra Space Solution

## The Core Idea

When you rotate an array right by `k`, every element just moves to a new index. The question is: **what is the new index for element at position `i`?**

Answer: **`(i + k) % n`**

That's the whole trick. Instead of physically shifting elements one-by-one (slow), you calculate directly where each element *should* end up, and place it there in one pass.

## Code

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> tmp(n);
        for (int i = 0; i < n; i++) {
            tmp[(i + k) % n] = nums[i];
        }
        for (int i = 0; i < n; i++) {
            nums[i] = tmp[i];
        }
    }
};
```

## Walking Through an Example

```
nums = [1, 2, 3, 4, 5, 6, 7]
k = 3
n = 7
```

We want each element to move 3 spots to the right (wrapping around at the end).

For each index `i`, compute `(i + k) % n` and put `nums[i]` there:

| i | nums[i] | (i + k) % n | tmp[that index] = nums[i] |
|---|---------|-------------|----------------------------|
| 0 | 1 | (0+3)%7 = 3 | tmp[3] = 1 |
| 1 | 2 | (1+3)%7 = 4 | tmp[4] = 2 |
| 2 | 3 | (2+3)%7 = 5 | tmp[5] = 3 |
| 3 | 4 | (3+3)%7 = 6 | tmp[6] = 4 |
| 4 | 5 | (4+3)%7 = 0 | tmp[0] = 5 |
| 5 | 6 | (5+3)%7 = 1 | tmp[1] = 6 |
| 6 | 7 | (6+3)%7 = 2 | tmp[2] = 7 |

So `tmp` fills up as:

```
tmp = [5, 6, 7, 1, 2, 3, 4]
```

Then the second loop just copies `tmp` back into `nums`:

```
nums = [5, 6, 7, 1, 2, 3, 4]
```

Check it: rotating `[1,2,3,4,5,6,7]` right by 3 should give `[5,6,7,1,2,3,4]`. ✅ Matches!

## Why `(i + k) % n` Makes Sense Intuitively

- Without the `% n`, element at index `i` just moves to `i + k`. That's straightforward — shift everything right by k.
- But if `i + k` goes *past* the end of the array (≥ n), it needs to **wrap around to the front**. That's exactly what `% n` (modulo) does — it "wraps" the index back into the valid range `[0, n-1]`.

**Example:** index 4 (value 5) with k=3 → 4+3 = 7, which is out of bounds (valid indices are 0-6). So it wraps around: `7 % 7 = 0`. That's why `5` ends up at index 0.

## Why Two Separate Loops?

- **First loop:** builds the fully rotated array into `tmp`, using the *original* `nums` values (so we don't overwrite something before we've read it).
- **Second loop:** copies `tmp` back into `nums`, since the problem wants the rotation done in-place on the original array.

You *can't* combine this into one loop over `nums` directly, because as soon as you overwrite `nums[some index]`, you might lose a value you still needed to read later.

## Complexity

- **Time: O(n)** — two simple passes over the array, no nested shifting like the brute-force solution.
- **Space: O(n)** — because of the extra `tmp` array.

This is a solid tradeoff: you spend O(n) extra space to bring the time down from O(n·k) to O(n), which is much better for large arrays or large k.

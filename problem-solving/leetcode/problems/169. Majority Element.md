# Majority Element — LeetCode Solution Explanation

## Problem

Given an integer array `nums` of size `n`, return the **majority element**.

The majority element is the element that appears **more than `⌊n / 2⌋` times**.

You may assume that the majority element always exists in the array.

**Example 1:**
```text
Input:  nums = [3,2,3]
Output: 3
```

**Example 2:**
```text
Input:  nums = [2,2,1,1,1,2,2]
Output: 2
```

## Code

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        sort(nums.begin(),nums.end());
        return nums[nums.size()/2];
    }
};
```

## How it works

The main idea is:

> If an element appears more than `n/2` times, then after sorting, it must be present at the middle index.

So we can solve the problem in two simple steps.

### Step 1: Sort the array

```cpp
sort(nums.begin(),nums.end());
```

First, we sort the array in ascending order.

For example:

```text
Before sorting:
[2,2,1,1,1,2,2]

After sorting:
[1,1,1,2,2,2,2]
```

After sorting, all occurrences of the same element are next to each other.

Since the majority element appears more than half of the total elements, it will always cross the middle position.

### Step 2: Return the middle element

```cpp
return nums[nums.size()/2];
```

After sorting, we simply return the element at the middle index.

For example:

```text
[1,1,1,2,2,2,2]
       ↑
     middle
```

The size of the array is `7`.

```text
7 / 2 = 3
```

So:

```cpp
nums[3]
```

is the middle element.

```text
[1,1,1,2,2,2,2]
       ↑
     index 3
```

Therefore, the answer is `2`.

## Why does the middle element always work?

This is the key idea of the solution.

The majority element appears **more than `n/2` times**.

That means it appears more times than all the other elements combined.

For example:

```text
nums = [2,2,1,1,1,2,2]
```

Here:

```text
n = 7
```

The majority element `2` appears `4` times.

```text
4 > 7/2
```

After sorting:

```text
[1,1,1,2,2,2,2]
```

The majority element occupies the last four positions.

The middle index is:

```text
7 / 2 = 3
```

And:

```text
nums[3] = 2
```

Therefore, the middle element must be the majority element.

## Why we don't need a HashMap

A common approach is to use a HashMap to count how many times each element appears.

For example:

```text
2 → 4
1 → 3
```

Then we can find the element whose frequency is greater than `n/2`.

However, this problem guarantees that a majority element always exists.

Because of this guarantee, we don't need to count frequencies.

After sorting, we can directly access:

```cpp
nums[nums.size()/2]
```

and get the majority element.

## Complexity

### Time Complexity: O(n log n)

The main operation is:

```cpp
sort(nums.begin(),nums.end());
```

Sorting `n` elements takes:

```text
O(n log n)
```

Accessing the middle element takes:

```text
O(1)
```

Therefore, the overall time complexity is:

```text
O(n log n)
```

### Space Complexity: O(1)

We don't create another array or HashMap.

We sort the given array directly.

Therefore, the auxiliary space complexity is:

```text
O(1)
```

## Complexity Summary

| Approach | Time | Space |
|---|---:|---:|
| Sorting | O(n log n) | O(1) |

## Edge Case: Single Element

Consider:

```text
nums = [5]
```

The array size is `1`.

```text
1 / 2 = 0
```

So:

```cpp
nums[0]
```

returns:

```text
5
```

Correct.

## Edge Case: Negative Numbers

The array can also contain negative numbers.

For example:

```text
nums = [-1,-1,2,3,-1]
```

After sorting:

```text
[-1,-1,-1,2,3]
```

Middle index:

```text
5 / 2 = 2
```

So:

```text
nums[2] = -1
```

Therefore:

```text
Output: -1
```

## Key Takeaway

The important observation is:

> **If an element appears more than half of the time, then after sorting, it must occupy the middle position.**

That's why these two lines are enough:

```cpp
sort(nums.begin(),nums.end());
return nums[nums.size()/2];
```

## Follow-up

The problem asks:

> Could you solve the problem in linear time and `O(1)` space?

Yes.

This sorting solution takes:

```text
Time: O(n log n)
Space: O(1)
```

But we can solve it more efficiently using the **Boyer-Moore Voting Algorithm**.

Boyer-Moore achieves:

```text
Time: O(n)
Space: O(1)
```

and avoids sorting the array completely.
